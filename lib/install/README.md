# Installer

`install.sh` sets up a machine from this repo: packages, stowed dotfiles, system files, services and external repos. `./install.sh -m` is a minimal install (no AUR, Rust, system files or services) and `./install.sh --server` a headless one. `uninstall.sh` reverses it. The `just` recipes run single steps (`just` lists them).

## Stowing

Each `home/<package>/` mirrors `$HOME` and is symlinked in with GNU Stow; `.stowrc` pins `--dir=home --target=~`, so a bare `stow <package>` from the repo root works for most packages. The exception is `NO_FOLD_PACKAGES` in `stow.sh` (`systemd`, `calendar`, `agents`, `plans`): systemd ignores drop-in and `.wants` directories that are symlinks, so these are stowed with `--no-folding`. `plans` is there because a folded `~/.local/lib` would put other programs' files into the repo. Use `just stow`/`restow` for them, never a bare `stow`, and add any new package that ships `~/.config/systemd/user` units or drop-ins to that list. `just migrate-systemd [--dry-run]` (`migrate.sh`) repairs a machine stowed folded.

## External repos

This repo has no submodules. `repos.sh` sets up every repo in `packages/repos.ini` (`owner/name`) plus the Neovim config under the gitignored `repos/`, cloned over HTTPS. `$GITHUB_DIR` (default `~/Development`) and `$GITHUB_ORG` (default `uhs-robert`) come from the environment or an ignored `install.local` in the repo root (environment wins; `lib/common/distro.sh` reads it). With `./install.sh --dev`, or when `$GITHUB_DIR/<section>/<name>` already exists, the checkout lives under `$GITHUB_DIR` and `repos/<name>` links to it, so there is only one copy. `just update-repos` pulls the non-linked clones.

Tracked files reach external repos only through `repos/`: theme files are relative symlinks into `repos/oasis.nvim/extras`, and `hyprvim` and `deserted-everything-css` link into `repos/`. Runtime configs that cannot find the checkout (shell rc files, Hyprland env) use `~/.local/share/dotfiles/repos`, which the installer links to `repos/`. `install_nvim_config` links `~/.config/nvim` to `repos/<name>` for `$NVIM_CONFIG_REPO` (default `uhs-robert/neovim`, or a git URL) and leaves an existing `~/.config/nvim` alone. The `symlinks` check step fails on a tracked symlink that dangles or leaves the repo, skipping links into a `repos/` clone not set up yet.

## Syncthing

`just syncthing` (also an opt-in prompt in `install.sh`, which `-y` never answers) installs Syncthing, enables its user unit with a drop-in that retries forever every 10 s and sets it for Tailscale only: it listens on this host's Tailscale IPv4, and global and local discovery, relays and NAT traversal are off. The GUI stays on `127.0.0.1:8384`. It writes nothing while Tailscale has no address. Discovery is off, so each peer needs its address: `just syncthing-peer <device-id> <tailscale-ip>`. `just syncthing-folders` then adds `<repo>-plans` and `<repo>-logs` for every repo `plans` finds (same scan as `plans ls --all`), each with 5 simple versions and an `.stignore`: `.*.tmp` for both, plus image and video extensions for logs (`(?d)`, so a host can delete a directory the other host removed). Conflict copies are not ignored. Share the folders from the laptop first, so its files win the first sync. Both steps edit `config.xml` with the service stopped and are safe to rerun.

## Agent host

`./install.sh --agent-host` is `--server` plus the packages in `packages/agent-host.ini` (the nested-session toolchain for the shadow bar) and `setup_agent_host` (`agent-host.sh`). The step runs `loginctl enable-linger`, stows `plans` when its unit is missing (`--server` stows no `plans`), installs the drop-in `lib/install/agent-host/plans-serve.conf` as `plans-serve.service.d/agent-host.conf` (`WantedBy=default.target`, and `PartOf=` cleared), writes `~/.config/plans/roots` when absent (`$GITHUB_DIR` and the dotfiles checkout) and enables `plans-serve`. Nothing else starts at boot: no greetd, no Hyprland, no bar. The stowed unit stays as is, so a laptop never gets the drop-in. It then prints the `remote.json` and `tailscale serve --bg --https=443 http://127.0.0.1:8765` steps for the owner. It is skipped under `--no-services`, and a rerun changes nothing.

`just agent-host-seed <host>` (`lib/install/agent-host-seed`, run on the laptop) copies once, with rsync over `ssh -o RemoteCommand=none`: `~/.local/state/quickshell/*.json`, `~/.local/state/hypr/*.json`, `~/.config/hypr/theme/.current_theme`, the FF7 lock audio and `~/.local/share/fonts` (`install_fonts` is skipped under `--server`, and the shadow bar reads fonts there). It never copies `weather.local.json`, and it never overwrites a file the host already has.

## Code

- `install.sh` only parses flags and calls functions; new install behaviour goes in the matching function here, not inline.
- `load.sh` loads `lib/common/output.sh`, `distro.sh`, `packages.sh` and every `install/*.sh`. Callers (`install.sh`, `uninstall.sh`, the justfile) set `DOTFILES_DIR` and source only it, so a file here must only define at source time (`tests/load.sh` enforces silence). `require_arch` (sets `$DISTRO`, dies off Arch) is called by `install.sh` and `uninstall.sh` only.
- `lib/common/` holds what `uninstall.sh` and the justfile share: `packages.sh` (manifests, pacman/pipx/luarocks), `distro.sh`, `output.sh` (`info`/`warn`/`success`/`die`), `greeter-files.sh` (the Quickshell files the greeter stages). The check steps and the Quickshell status source `greeter-files.sh` or `greeter.sh` directly.
- One concern per file: `arch.sh` (paru, AUR), `rust.sh`, `fonts.sh`, `stow.sh` (stowing, `NO_FOLD_PACKAGES`, generated defaults), `dev-tools.sh` (runtimes, tmuxifier, git identity and hooks, Neovim), `system.sh` (system files including the uinput udev rule for ydotool and the `user@.service` CPUWeight drop-in (then `daemon-reload`), shell, keyd, power profiles, root symlinks), `hardware.sh` (Nvidia, xone, Steam), `snapper.sh`, `greeter.sh` (greetd, the Quickshell greeter, keyring unlock, `monitors.lua` from `greeter-monitors.lua`), `voice.sh` (voxtype, voxcmd's Firefox host and extension policy), `calendar.sh`, `repos.sh`, `artcraft.sh` (the prompt for the ArtCraft apps), `migrate.sh` (one-time layout migrations), `tailnet-ssh.sh`, `syncthing.sh` (two-machine sync of each repo's `.plans` and `.logs`, see Syncthing), `agent-host.sh` (the `--agent-host` profile, see Agent host).

- `desertfox-freshness` is a script, not a library (no `.sh`, so `load.sh` does not source it). The `desertfox-config` recipe in the justfile runs it to warn when the DesertFox checkout is behind its upstream or its `dist/` is stale.
- `agent-host-seed` is a script too (see Agent host), and `agent-host/` holds the `plans-serve` drop-in that `setup_agent_host` installs.
- `artcraft-update` is a script too. It installs or updates the apps in `packages/artcraft.ini` from their GitHub releases. It accepts a package only when `SHA256SUMS.txt` carries a signature from the pinned ArtCraft key and the package matches its checksum. `install_artcraft`, `just artcraft-update` and topgrade's "ArtCraft apps" command run it.
- Tests: `tests/`. What gets installed is in [`packages/`](../../packages/README.md).
