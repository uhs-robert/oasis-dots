# Ship a batch

## Scripts

- Bring a branch up to date with `.claude/skills/ship-batch/rebase-branch.sh <branch>`, never by merging `origin/main` in or a bare force-push (both blocked or costly): it rebases, then pushes with `--force-with-lease`, and refuses `main`, a branch with no open PR or one whose remote has commits it lacks.
- Before running it, every branch is rebased on `origin/main`, pushed and has an open PR (step 1); afterwards tick the finished items in `review.md` if one exists (step 4).
- `.claude/skills/ship-batch/ship-batch.sh <n>...` with the PRs in merge order, as that bare command: a prefixed variable no longer matches the owner's allow rule and is blocked.
- `--request-review` goes before the PR numbers, only for a material fix: it lets the review wait comment `@codex review` on a PR changed past the small-fix limit since its review. Without it the gate reports that as a problem.
- `--skip-review-gate` goes before the PR numbers, only when the owner waived the reviewers or the piece's approved review tier is trivial; it skips reviewer states (no waiting, no requests), unresolved threads still block, and it applies to every PR in the run, so a piece shipped with it goes in its own run, never in a batch with other pieces. Say so in the PR.
- When the gate gives up waiting on a review (Codex "still running" after its wait), do not rerun: ask the owner whether to merge with `--skip-review-gate`.
- Merge only through this script, never `merge-prs.sh <n>` or `gh` directly.
- Main is not checked after a merge: each branch is checked once, before it merges. Run `just check` in the main checkout when its state matters.
- With no PR numbers it resumes an interrupted run.

## Details

The only way to merge PRs in this repo, never `merge-prs.sh <n>` or the `gh` merge command directly. Use it once merging is approved: the owner said to merge, or a standing approval covers the PR (what meets it is in the orchestrator skill's `review-fallback.md`).

1. For each branch: rebase on `origin/main` if it is behind, push, and `gh pr create` written with the global `pr-descriptions` skill, plus a note if a gating reviewer was Unavailable or NotStarted.
2. Run `.claude/skills/ship-batch/ship-batch.sh <n>...` from anywhere in the repo, PRs in merge order, as that bare command: do not prefix `HYPRLAND_INSTANCE_SIGNATURE=...` or any other variable, because a prefixed command no longer matches the owner's allow rule for the script and is blocked. When `HYPRLAND_INSTANCE_SIGNATURE` is unset or stale, the script finds the owner's live Hyprland itself (the newest instance under the owner's `$XDG_RUNTIME_DIR/hypr` that answers `hyprctl version`, never a shadow's nested one) before its first `hyprctl`, and names the instance on stderr; it dies with a clear message when none answers. It works in two phases:
   - **Before the lock**, for each PR in turn: wait for its gating reviewers (Codex, CodeRabbit) with the global `merge-prs` skill's gate (`merge-prs.sh --check --wait-review`, so a running review is waited out; a head that changed past the small-fix limit since its review is reported as a problem for the orchestrator to settle, unless `--request-review` was given, which requests one: only for a material fix; a piece whose tier waives the review ships with `--skip-review-gate`), while its branch is checked with `lib/check.sh --changed origin/main` (concurrently with the wait; the check's output is shown once both finish, and there is no rerun after the merge), in the branch's local worktree or, when it has none (pushed from a cloud session), in a temporary worktree at the PR head (`git fetch origin pull/<n>/head`, removed on every exit path). A branch that does not contain `origin/main` is refused unchecked: step 1 rebases it, because the one check must be of what main becomes. The PRs of one batch are each checked against main, never together. The first PR that fails its gate or check stops the list: the PRs before it still merge, and the run ends by failing with the PR to rerun from.
   - **Under the lock** (`flock` on `ship-batch.lock` in `$(git rev-parse --git-common-dir)`), only what must be serial on the main checkout: merge the ready PRs with `merge-prs.sh` (gate only, never waiting; refuses a PR not based on the default branch, removes merged clean worktrees and branches), pull `main`, `just restow <package>` for every package stowed here that gained, lost or renamed a file (a pull alone leaves a new unit or script unlinked), `just migrate-quickshell-state` if the merge touched `lib/install/migrate.sh`, `lib/install/load.sh`, `install.sh` or the `justfile` (an edit alone restows nothing; run before the bar restart and, when the bar restarts, again with the old bar stopped so cleanups that need no bar happen; a failure stops the run, after relaunching the bar if it was already stopped, and a rerun resumes), `just voxcmd-build` if the merge touched `home/voxcmd/src` or its `Cargo.toml`/`Cargo.lock` (so the installed Rust voxcmd is never stale; a failed build prints a WARNING, sends a critical notification and never fails the run, and rerunning the command by hand fixes it), `systemctl --user daemon-reload` if a user unit changed, reload Hyprland if `home/hypr` changed, restart the stowed bar if `home/quickshell` changed and the lock is `unlocked` (with `restart-bar.sh stop`, the second migration, then `restart-bar.sh start`; a bar that survives SIGKILL or does not come back fails the run and keeps the base, so a rerun resumes), and `just greeter-sync --install` if the merge changed greeter files and sudo needs no password (otherwise it prints the command). Before merging, it fetches `origin/main` and refuses any checked branch that no longer contains it (another batch merged since): that PR and the ones after it are left unmerged with "main moved since <branch> was checked", and a rerun checks them again. A second ship-batch waits for the lock, naming the holder (pid, start time, PRs), for up to `SHIP_BATCH_LOCK_WAIT` seconds (default 900), then gives up.

   Pass `--skip-review-gate` before the PR numbers (a flag after one is rejected) only when the owner waived the reviewers or the orchestrator skill's approved trivial-tier or non-material-fix waiver applies: it skips the reviewer states (the waits and requests) but not the unresolved-thread check, which still runs before the lock as `merge-prs.sh --check --skip-review-gate`, and passes the flag to the merge, while each branch check still runs; say so in the PR.

   With no PR numbers it only does the locked steps. Resuming: under the lock it records main's commit in `ship-batch-base` (next to the lock) and deletes it only after every reload, restart and sync succeeded, so a rerun after an interrupted merge or reload prints `resuming from <sha>` and redoes them from there. A recorded commit main no longer descends from reloads everything. `tests/run.sh` covers the base selection, the lock, which packages get restowed, the branch check, and a whole batch against stubs (what runs inside and outside the lock, a partial batch, a failed or slow check that must stop the merge).
3. `ship-batch.sh` ends by running `~/.claude/skills/merge-prs/status.sh`; run it again whenever the owner asks what is left, and report what it lists.
4. Tick the finished items in `review.md` and update its handoff if one exists.
