# Ship a batch

## Scripts

- Before running it, every branch is rebased on `origin/main`, pushed and has an open PR (step 1); afterwards tick the finished items in `review.md` if one exists (step 4).
- `.claude/skills/ship-batch/ship-batch.sh <n>...` with the PRs in merge order, as that bare command: a prefixed variable no longer matches the owner's allow rule and is blocked.
- `--skip-review-gate` goes before the PR numbers, only when the owner waived the reviewers; it skips reviewer states (no waiting, no requests), unresolved threads still block. Say so in the PR.
- Merge only through this script, never `merge-prs.sh <n>` or `gh` directly.
- `ship-batch.sh --wait-main-check`, in the background, is the only way to know main is green. A failed main check warns and never blocks; fix it with a small follow-up PR first.
- With no PR numbers it resumes an interrupted run.

## Details

The only way to merge PRs in this repo, never `merge-prs.sh <n>` or the `gh` merge command directly. Use it once merging is approved: the owner said to merge, or a standing approval covers the PR (what meets it is in the orchestrator skill's `review-fallback.md`).

1. For each branch: rebase on `origin/main` if it is behind, push, and `gh pr create` written with the global `pr-descriptions` skill, plus a note if a gating reviewer was Unavailable or NotStarted.
2. Run `.claude/skills/ship-batch/ship-batch.sh <n>...` from anywhere in the repo, PRs in merge order, as that bare command: do not prefix `HYPRLAND_INSTANCE_SIGNATURE=...` or any other variable, because a prefixed command no longer matches the owner's allow rule for the script and is blocked. When `HYPRLAND_INSTANCE_SIGNATURE` is unset or stale, the script finds the owner's live Hyprland itself (the newest instance under the owner's `$XDG_RUNTIME_DIR/hypr` that answers `hyprctl version`, never a shadow's nested one) before its first `hyprctl`, and names the instance on stderr; it dies with a clear message when none answers. It works in three phases:
   - **Before the lock**, for each PR in turn: wait for its gating reviewers (Codex, CodeRabbit) with the global `merge-prs` skill's gate (`merge-prs.sh --check --wait-review --request-review`, so a running review is waited out and a head that changed since its review gets one requested), then check its branch with `lib/check.sh --changed <merge-base with origin/main>`, in the branch's local worktree or, when it has none (pushed from a cloud session), in a temporary worktree at the PR head (`git fetch origin pull/<n>/head`, removed on every exit path). Steps that already passed for the same files are skipped, so an already-checked branch costs nothing; a pass on top of a base recorded as passed is recorded for the branch's tree. The first PR that fails its gate or check stops the list: the PRs before it still merge, and the run ends by failing with the PR to rerun from.
   - **Under the lock** (`flock` on `ship-batch.lock` in `$(git rev-parse --git-common-dir)`), only what must be serial on the main checkout: merge the ready PRs with `merge-prs.sh` (gate only, never waiting; refuses a PR not based on the default branch, removes merged clean worktrees and branches), pull `main`, `just restow <package>` for every package stowed here that gained, lost or renamed a file (a pull alone leaves a new unit or script unlinked), `just migrate-quickshell-state` if the merge touched `lib/install/migrate.sh`, `lib/install/load.sh`, `install.sh` or the `justfile` (an edit alone restows nothing; run before the bar restart and, when the bar restarts, again with the old bar stopped so cleanups that need no bar happen; a failure stops the run, after relaunching the bar if it was already stopped, and a rerun resumes), `just voxcmd-build` if the merge touched `home/voxcmd/src` or its `Cargo.toml`/`Cargo.lock` (so the installed Rust voxcmd is never stale; a failed build prints a WARNING, sends a critical notification and never fails the run, and rerunning the command by hand fixes it), `systemctl --user daemon-reload` if a user unit changed, reload Hyprland if `home/hypr` changed, restart the stowed bar if `home/quickshell` changed and the lock is `unlocked`, and `just greeter-sync --install` if the merge changed greeter files and sudo needs no password (otherwise it prints the command). A second ship-batch waits for the lock, naming the holder (pid, start time, PRs), for up to `SHIP_BATCH_LOCK_WAIT` seconds (default 900), then gives up.
   - **After the lock**, the check of main (`main-check.sh`) runs in the background and ship-batch returns. A running check from an earlier batch is stopped first (it verifies a main the pull replaces; its owed base is untouched): before the first branch check, when no other batch holds the lock, so branch steps do not wait behind it, and again under the lock. The new one starts from the oldest owed base, as `systemd-run --user --unit=dotfiles-main-check-<8 hex of the git common dir's sha256> --collect` (`MAIN_CHECK_UNIT` overrides the name) at Nice 19 with the session's display, D-Bus and SSH agent variables (`setsid` when that is unavailable). A run that stopped a check and then dies (a failing branch check, merge or reload) starts it again on the way out, so a debt is never left with nothing running. Which check runs: a tree recorded as passed with `repos/` is not checked again, one passed in a worktree (no `repos/`) runs only `lib/check/steps/symlinks.sh`, a previous main recorded as passed runs `lib/check.sh --changed <previous main>`, anything else (or `CHECK_FULL=1`) runs the full `just check`. The two lookups cost seconds and run in the foreground. The log and the result (`pass <sha>` / `fail <sha> <log>` / `unrecorded <sha> <log>`) are `ship-batch-main-check.log` and `.result` in the git common dir; only a pass clears the owed base, and a pass of a main checkout with local changes to tracked files is `unrecorded` and clears nothing. Pass `--sync-check` (or `SHIP_BATCH_SYNC_CHECK=1`) to wait for the check in the foreground and fail the run when it fails; a newer batch that stops that check makes the run print "superseded" and exit 0, the debt passing to that batch.

   **Waiting for main**: `ship-batch.sh --wait-main-check` (run it in the background; it is the only way to know main is green) blocks while a check runs (or a batch has it stopped for its branch checks, up to `MAIN_CHECK_WAIT_SECS`) and exits 0 when nothing is owed, 1 when the last check failed (with the log tail) or a check is owed but not running (rerun `ship-batch.sh` with no arguments). `.claude/skills/ship-batch/main-check.sh status` prints running, owed and the last result.

   **A failed check is a warning, never a block.** The owner gets a critical desktop notification, the owed base stays, ship-batch prints a FAILED banner first and last on every run, and a SessionStart hook (`.claude/hooks/report-failed-main-check.sh`) prints the same one-line notice at the start of every session in this repo. Merges are not refused, so the fix PR ships normally.

   Pass `--skip-review-gate` before the PR numbers (a flag after one is rejected) only when the owner waived the reviewers: it skips the reviewer states (the waits and requests) but not the unresolved-thread check, which still runs before the lock as `merge-prs.sh --check --skip-review-gate`, and passes the flag to the merge, while each branch check still runs; say so in the PR.

   With no PR numbers it only does the locked and post-lock steps. Resuming: under the lock it records main's commit in `ship-batch-base` (next to the lock) and deletes it only after every reload, restart and sync succeeded, so a rerun after an interrupted merge or reload prints `resuming from <sha>` and redoes them from there. The check is owed separately in `ship-batch-check-base`, written under the lock (an older debt is kept) and cleared only when main's check passes, so a rerun after a failed, stopped or interrupted check (with the PRs not yet merged, or none) checks again from the oldest unchecked main; with nothing new and nothing owed it checks nothing. A recorded commit main no longer descends from reloads everything and falls back to the full check. `tests/run.sh` covers the base selection, the lock, the owed check, which packages get restowed, and a whole batch against stubs (what runs inside and outside the lock, a partial batch, a failed check and its rerun).
3. `ship-batch.sh` ends by running `~/.claude/skills/merge-prs/status.sh`; run it again whenever the owner asks what is left, and report what it lists.
4. Tick the finished items in `review.md` and update its handoff if one exists.

If the check of `main` fails (the FAILED banner, notification or session notice), fix it with a small follow-up PR before anything else and tell the owner.
