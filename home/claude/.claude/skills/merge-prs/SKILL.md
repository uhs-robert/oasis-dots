# Merge PRs

Only after the owner has approved the merge. Run from anywhere inside the repo, PRs in merge order:

```bash
~/.claude/skills/merge-prs/merge-prs.sh [--method rebase|squash|merge] [--keep-branch] [--skip-review-gate] [--wait-review] <pr>...
```

- Before merging anything it checks every PR, and stops naming each problem if one has an unresolved review thread or a gating reviewer that is still running or failed (fix it, or comment the reviewer's request, e.g. `@codex review`, and wait, then rerun). Which reviewers gate comes from `orchestrator/reviewers.sh`: gate `never` is skipped, `always` is waited for, `auto` only when the reviewer is installed on the repo (an app's check suite on the default branch, or a commenting bot among the last 10 PRs' comments). Per reviewer: Codex is read from its summary comment (the `codex-review-state` marker, else the status table); a PR with no summary yet counts as running when Codex has put its eyes reaction on it, and as not started while it is younger than 5 minutes (`MERGE_PRS_REVIEW_START`, seconds, also CodeRabbit's `start_s`), after which a reviewer that never started is a note, not a block. CodeRabbit is read from its check run on the head: running or queued blocks, and success counts as done once a CodeRabbit review of the head exists, or, for a clean pass that posts none, `settle_s` (180 s, `MERGE_PRS_SETTLE`) after the check finished if its summary's coverage marker names the head; a marker naming an older commit keeps waiting. A cancelled or stale run is pending until `start_s` passes, then failed; `action_required` is failed at once and never re-requested; any other unlisted conclusion is failed with its value. A reviewer that posted a usage-limit or rate-limit comment after the head commit, or whose check concludes with an `unavailable_conclusions` value, is unavailable: a note, not a block; mention notes to the owner. `--wait-review` waits for a running or not-yet-started review instead, polling every 20 s for up to 20 minutes per reviewer (`MERGE_PRS_REVIEW_POLL`, `MERGE_PRS_REVIEW_WAIT`), and asks once more (the reviewer's `request`) after a failed one, then applies the gate as usual. A Codex review of an older commit than the head passes with a note when the commits after the reviewed one (matched by sha) together change at most 20 lines (generated paths excluded), only in files the review covered, whatever their subjects; more lines, a file the review never saw, or a change with no countable lines (binary, mode-only, submodule) needs its own review: the gate stops, or with `--wait-review` it comments `@codex review` and waits for a review of the head (under `--check` only with `--request-review`). A Codex summary that says Completed but records no commit (quota, outage) means nothing was reviewed: the gate reports it as unreviewed and never compares against it; `--wait-review` (under `--check`, with `--request-review`) comments `@codex review` once and waits for a summary with a commit. Rebases do not count as changes, since each side is compared with the default branch. A repo with committed build output lists its generated path prefixes in `.claude/generated-paths` (one per line, `#` comments): a later commit touching only those paths is ignored by the gate, with a note, and generated files never count as files the review never saw. `--skip-review-gate` is for when the owner explicitly waived the reviewers: it skips their states (no waiting, no requests) but unresolved threads still block.
- `merge-prs.sh --check <pr>...` runs only that gate and exits 0 when every PR passes: use it before telling the owner a PR is ready. It changes nothing (a review request under `--request-review` aside), and cannot be combined with `--method` or `--keep-branch`; it takes `--skip-review-gate` (threads only), `--wait-review`, and with it `--request-review`, so a caller can wait for every review before it merges (ship-batch does).
- The method defaults to the first of rebase, squash, merge the repo allows; `--method` forces one.
- Every PR must be based on the default branch and come from this repository: otherwise the run stops before merging anything, naming the PR (`#7 is based on x, not main`). Stacked PRs and fork PRs are not supported; base the PR on the default branch.
- A PR that GitHub reports as conflicting is rebased onto its base and force-pushed with a lease only when that drops a generated-only commit the pre-merge step rebuilds (see below); any other conflict stops the run for the owner to rebase by hand.
- A repo can add an executable `.claude/pre-merge`, run for each PR right before its merge in a temporary worktree at the PR head, with `MERGE_PRS_PR`, `MERGE_PRS_BRANCH`, `MERGE_PRS_BASE` and `MERGE_PRS_REPO_ROOT` set. A head behind its base is first rebased onto it (rebase and squash only), dropping commits that touch only generated paths since the step rebuilds them. If it commits, the commit is pushed (no force) and that exact head is merged; a non-zero exit stops the run before that PR. `--check` never runs it.
- Clean worktrees of merged branches are removed and the branches deleted, switching a clean main checkout off a merged branch to the default branch first; dirty ones, and branches with commits not in a PR head seen this run, are kept with a warning. `--keep-branch` keeps the remote branch and skips local cleanup.
- A PR in the list that is already MERGED (an interrupted earlier run merged it) counts as done: it prints `#N already merged`, still removes its clean worktree and local branch, and the run goes on with the rest. Nothing is pushed for it, and a branch whose PR head is not available locally is kept. A closed PR still stops the run.
- A queued merge is polled for up to `MERGE_PRS_WAIT` seconds (default 600).
- The main checkout is pulled only when it is on the default branch with no tracked changes.
- Never append cleanup (`git branch -D`, `git push origin --delete`) after the script, and never put it behind `;` or a `| tail` pipe, which hides the merge's exit code. The script does its own cleanup; a failed merge followed by a remote branch delete closes the PR for good. Run any manual cleanup as a separate command after reading the result.
- Review threads: reply and resolve with `~/.claude/skills/merge-prs/resolve-thread.sh <PRRT_id> "<reply>"` (`-` as the reply reads stdin), and list the unresolved ones with `--list <pr>` (id, path, line, author, first line). Run it bare, with no `VAR=x` prefix, or the allow rule no longer matches. Raw `gh api graphql` reply/resolve mutations are denied by a hook.

It stops at the first failure with the reason; fix it, then rerun with the PRs not yet merged. Report each output line that needs the owner (skipped worktrees, skipped pull, stale local branches).

As the final step, and whenever the owner asks what is left, run `~/.claude/skills/merge-prs/status.sh` from anywhere in the repo: a read-only summary of your open PRs, other worktrees, unmerged local branches, untracked files and the main checkout. It also runs the repo's executable `.claude/status.d/*.sh` scripts and prints each one's output under its name.

After changing `merge-prs.sh`, run `tests/run.sh`: it replays merges, refusals, conflicts, the pre-merge step and the reviewer gate against a local origin and a fake `gh`.
